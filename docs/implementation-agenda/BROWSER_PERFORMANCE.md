# Browser performance acceptance

`tools/test_issue_performance_ui.cjs` measures the actual archive interface in headless Chromium on the CI host. It uses the production worker, selective historical client, IndexedDB, report renderer, download and reopening paths. The invented deterministic fixture contains 193 country labels, two policies, 4,246 annual observations and 2,123 source identities across eleven partial/full calendar-year portions of a rolling ten-year window. These are engineering records, not statements by real countries, an empirical benchmark or evidence of historical coverage.

The measured intervals run from Generate report click through the corresponding ready state and settled layout, from Save report click through downloaded bytes being readable, and from saved-file selection through the reopened state and settled layout. Layout timing includes two animation frames and a geometry read; all 192 country articles and 772 policy/country charts must actually exist. A generation must make a new manifest request, preventing an old ready message from satisfying a warm-run wait. The warm run must use the verified analytical-result cache and avoid additional shard downloads. Saving, warm regeneration and reopening must preserve exact inputs, exclusions, summary, evidence and results. Reopening uses a fresh browser context with an empty IndexedDB cache and must fetch no source shards. The visible substantive overview and its saved version must exist and remain identical across cold, warm and reopened reports.

Initial host-specific budgets are 15 seconds for cold generation, 8 seconds for warm cached generation, 8 seconds for frozen reopening and 8 seconds for saving/downloading. The fixture also caps selected source bytes at 10 MB, saved-report bytes at 20 MB and rendered DOM elements at 200,000; desktop and 390-pixel layouts must fit the page width. These provisional engineering ceilings are measured on the recorded host, not a promise for arbitrary computers, all datasets or every ten-year workload. The test records Chromium and Node versions, operating system, CPU, available system memory, workload counts, selected bytes, saved bytes, SVG count and DOM count.

Only a small JSON metrics artifact is retained. Downloaded reports are deleted after verification; the test creates no large screenshots or durable source-bearing fixture files. CI installs its normal browser harness. No local browser dependency installation or end-user installation is required. Authoring or syntax-checking this test is not measured performance acceptance: actual CI execution and its metrics must be inspected before claiming these budgets passed.
