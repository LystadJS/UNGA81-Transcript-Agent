# Private owner-review delivery

The original training reviewer remains in the private HF dataset at its pinned revision. `owner-training-export.yml` provides a read-only delivery path when the owner's current workspace has no HF credential. Maintainers dispatch it with a locally generated RSA-4096 **public** key. The corresponding private key must remain outside Git and must never be sent to Actions.

The runner verifies the pinned reviewer/packet hashes and a strict six-file training-only allowlist. It reads no calibration or sealed-test originals and never restores the whole archive. Only the original 180 unreviewed training examples are eligible. Payload ZIP bytes stay in memory and are encrypted using a fresh AES-256-GCM key, with RSA-OAEP/SHA-256 key wrapping and an authenticated versioned header. The one-day Actions artifact contains ciphertext only. No credentials, passages, owner annotations or decryption keys are logged or attached as plaintext.

The authorized private workspace verifies the GitHub artifact digest, decrypts with its local private key, checks the inner file manifest, and builds the requested user download outside the code repository. The public key can be retained in workflow inputs; possession of it cannot decrypt the artifact. This workflow changes no dataset, collection selection, canonical pointer or model.

For full returned-review validation, explicitly set the manual workflow input `include_registration` to `true`. The default remains the original six-file export. This option adds only `01_training/provenance/registration.json`, verified against the pinned original packet checksum and the training draft's registration digest. Its strict metadata schema allows prospective source identities, dates, splits, hashes, policy propositions and method identifiers. It rejects passage text, label/annotation fields, nested payloads and unknown fields. The existing forward-date and source-disjoint split checks still apply. Calibration/test **metadata** is needed to validate prospective separation; calibration/test source originals and labels are never requested. The resulting seven-file bundle uses the same recipient encryption and per-file manifest checks.

Use those original inputs with the [private intake command](PILOT_REVIEW.md#validating-returned-reviews), preserving the owner's returned choices. Successful local reconciliation does not imply canonical private-HF ingestion, completed review, or accepted model performance. Missing reviewer identity or confirmation requires actual owner correction; never synthesize it.

Cryptographic operations use the open-source `cryptography` package pinned to 46.0.3 in the runner and CI (Apache-2.0/BSD-3-Clause project licenses). No custom encryption primitive is implemented. Synthetic tests cover authenticated round-trip, ciphertext tampering, wrong recipients, private-key rejection, training-only reads and original-file hash mismatch.

The final owner ZIP should include the browser reviewer, original training provenance, review guidance, the current issue catalog/model policy, and checklists for already identified owner-only operational/usability decisions. Distinguish material ready for review from unavailable or later-stage work. Do not treat delivery, a checkbox, or assistant QA as human gold or scientific acceptance.


## Encrypted return into canonical private storage

`owner-review-intake.yml` adds manually dispatched `prepare`, `part` and `finalize` actions. All actions use the same `operational-store` concurrency group as the warehouse. No action trains a model, expands publication rights or changes the warehouse's `latest.json`.

1. Dispatch `prepare` on the reviewed main branch. The runner creates an RSA-4096 recipient key with a 24-hour intake window. The private key and its hash-bound metadata are committed and verified only in the private HF dataset. The public artifact contains only its public key, immutable revision, identifier, expiry and transfer bounds.
2. Download that artifact from the known repository/run/head and verify the GitHub artifact SHA-256 before trusting its recipient key. Keep unpacking bounded and accept only `owner-intake-result.json`. A substituted recipient key could expose a return, so an unverified file or third-party key is not acceptable.
3. In the authorized private workspace, run `PYTHONPATH=src:. python tools/receive_owner_review.py pack --recipient PRIVATE/owner-intake-result.json --returned PRIVATE/un-pilot-reviewed.json --output PRIVATE/encrypted-dispatches`. The tool preserves the exact original bytes, compresses them, then uses the existing authenticated AES-256-GCM/RSA-OAEP envelope. It produces numbered dispatch JSON files containing ciphertext only. Never paste plaintext review JSON, private keys or tokens into workflow inputs.
4. Dispatch each numbered part in order using `gh api --method POST repos/LystadJS/UNGA81-Transcript-Agent/actions/workflows/owner-review-intake.yml/dispatches --input PRIVATE/encrypted-dispatches/N.json`. Wait for that run's successful, verified receipt before submitting the next part; the final numbered file requests `finalize`. Never enqueue a backlog of writers: GitHub concurrency retains only one pending job per group.
5. Finalization checks the complete ciphertext hash and recipient, rejects decompression overflow/extra streams, validates the returned JSON and reuses the frozen training/registration intake. It combines an existing validated partial subset without replacing conflicting choices or reviewer identities. Only after every private output has been reread and verified does an atomic commit advance `owner-intake/train/latest.json`, add the accepted-input receipt and consume the recipient. Source/model warehouse pointers are untouched.

The return limit is 2 MiB before compression, 256 KiB ciphertext and at most eight 48,000-character base64 parts. Every dispatch remains below GitHub's input bound. Duplicate identical parts are safe; differing bytes at the same index are rejected. Missing parts, source/label conflicts, expired keys, unknown JSON fields in stored manifests, failed metadata calls, incomplete capacity accounting and parent-commit changes stop publication. Original returned bytes, validated cumulative training labels, their manifests and a separate consistency-flag ledger stay private. Collective/national attribution conflicts are marked as assistant provisional QA requiring owner clarification; no owner choice is replaced. Normal replay re-verifies accepted files without a new commit; a response lost after activation is recovered through the consumed-recipient receipt. After an unactivated staging failure, use a fresh finalize run identity rather than overwriting the immutable staged directory.

History-aware budget checks precede writes and include a 1 MB reserve for pointer/receipt overhead. Temporary encrypted parts and private recipient keys remain in private version history and count toward capacity; there is no automatic pruning or paid upgrade. The private key is a transport key, never an HF account token. Only approved maintainers may dispatch this workflow. Public receipts contain aggregate counts, verification flags and opaque revision/key IDs, never source text, reviewer names, annotations or private keys. Aggregate file consistency is not independent human agreement or model acceptance.
