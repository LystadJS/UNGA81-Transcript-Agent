# I7: nine further numerical implementations

The standalone research layer now implements 27 of the 30 methods outside the
daily pipeline. The daily pipeline still has 12 adapters. Synthetic acceptance
does not establish diplomatic validity, integrate reviewed datasets, or release
results into O1–O5. All research calls still reject real/unreviewed inputs.

## Added methods and precise limits

| ID | Executable scope | Remaining scientific work |
|---|---|---|
| M14 | Bernoulli gradient-boosted trees, fixed 150 trees/depth 2; separate Platt calibration and held-out evaluation | Label learning curves, tuning using training-only validation, real-text benchmark |
| M18 | Variational LDA; fixed vocabulary; infer from observed evaluation words and score held-out words | Topic-count selection, restart stability/coherence, human interpretation |
| M19 | Structural topic model with up to three numeric prevalence covariates; new-document inference and completion scoring | Substantive covariate specification, topic stability, content covariates and uncertainty analysis |
| M20 | Unit-normalized cached passage embeddings, HDBSCAN, class TF-IDF descriptors, nearest-centroid source passage exemplars | Approved encoder inference, human topic review, density sensitivity; this is not the full BERTopic package |
| M28 | Gaussian HMM fit on earlier observations, forward-only filtering on evaluation sequences | State-count/restart sensitivity, observation comparability, real backtests |
| M29 | Latent transition model with two binary, conditionally independent, time-invariant measurement items | Measurement invariance is imposed; it still needs substantive and empirical testing |
| M30 | Gaussian Markov-switching dynamic mixture with a lagged numeric transition covariate | Transition specification, nonlinear alternatives, predictive backtesting |
| M35 | Symmetric Bernoulli stochastic block model, ICL selection within 1–4 groups | Resampling stability; weighted/missing-edge likelihoods are unsupported |
| M42 | First-event complementary-log-log hazard, Gaussian partial pooling, four-chain Metropolis sampling, rank-normalized R-hat and bulk/tail ESS, posterior predictive event counts | Group standard deviation is fixed at 1, not inferred; prior sensitivity, held-out prediction and causal identification remain absent |

M14 inherits country/content/observation disjointness and strict forward-time
partitions. Its hyperparameters are fixed before calibration and testing.
M18/M19 require distinct training and evaluation document IDs. The caller must
construct genuinely disjoint observed/held-out token subsets; count matrices
alone cannot prove token provenance. Vocabulary is fixed before evaluation.

M28–M30 fit parameters only on earlier training observations. Evaluation
sequences restart from the learned initial distribution; they do not silently
continue training histories. Only forward probabilities are returned for
evaluation. Training models may retain smoothed training diagnostics. The known
fractional binomial EM-weight warning is retained in `fit_warnings`; other
fitting warnings stop the call. One seeded initialization does not establish
the global likelihood optimum.

M35 accepts a complete observed binary network, with no self edges or missing
dyads. A cosine matrix or an unknown edge is rejected. Membership is not evidence
of a political alliance. M42 preserves the existing first-event, exposure-time,
equal-duration and censoring contracts. Its grouping describes exchangeability,
not an observed causal diffusion mechanism. A failed sampler screen returns
`quality_state=withheld_sampler_diagnostics` and `sampler_pass=false`.

## Remaining three kernels

- **M16, fine-tuned text transformer:** no approved checkpoint/tokenizer or
  reviewed training/evaluation labels have been supplied. The implementation,
  training loop and resource/learning-curve benchmarks remain unwritten. A
  random toy transformer would not satisfy this registered method.
- **M26, driftmapR movement/resampling:** the registry refers to an earlier
  experimental adapter and supported-regime study, but supplies no package
  source/version or study artifact. No verified public interface was identified.
  This name must be resolved before building the exact adapter; a generic
  resampling method must not be relabeled driftmapR.
- **M38, temporal transformer/sequence model:** no approved sequence specification,
  comparable long historical panel or neural runtime is present. Architecture,
  training and comparison against the M37 baseline remain unwritten. Its
  observation unit, sequence length and prediction horizon need to be established
  from the dataset rather than assumed from the daily calendar.

These are explicit outstanding implementation tasks, not newly completed
methods. The [dataset guide](../docs/DATA_GUIDE.md) remains the next step for real
labels, stance, historical and event data. There is still no reviewed-bundle
loader or path from these kernels to the daily release machinery.

## Reproduce

Run from the repository root:

```powershell
Rscript research/setup.R
Rscript research/test_engines.R research/library
Rscript research/test_more.R research/library
python tools/test_review_data.py
```

The new backends are checked against the versions actually tested:
gbm 2.3.1, topicmodels 0.2.17, stm 1.3.8, depmixS4 1.5.4,
blockmodels 1.1.5, posterior 1.7.0. `setup.R` installs missing dependencies;
it does not silently downgrade an installed version. A different version needs
explicit retesting and a source change to the version contract. Use a project
library; the daily pipeline's frozen dependency identity remains separate.

For numerical reproducibility and bounded execution, use one BLAS/OpenMP thread.
The topic-model wrapper temporarily sets and restores this with RhpcBLASctl;
the I7 test entry point also uses a single thread. An initial
multithreaded STM smoke run took several minutes; the complete I7 suite took
seconds with a single thread. This is a local observation, not a production
performance benchmark.

`run.R` now hashes both engine source files and records the new backend versions.
It retains immutable output names, input hashing and explicit non-publication.
Test fixtures in `test_more.R` are the input schema examples. No model downloads,
external inference calls, private labels or credentials are included.
