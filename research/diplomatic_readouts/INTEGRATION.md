# Coordinator-only integration contract (no worker edits outside this directory)

1. **Acceptable sources:** First validate the upstream input through the canonical `un.browser.corpus.v1`, `un.passage-corpus.v1`, or `un.review.v1` authority, with immutable original identity, distinct raw-bytes/text SHA-256, source URL, representation/transformation version, parent/meeting/speech lineage and declared split. For a `un.parallel-analysis.v1` output, apply both its JSON Schema and its *relational invariants*, including observation/model coverage, failures, model representation, and source/text hash joins. Do not treat schema-valid analysis exports as accepted evidence by default.
2. **Population audit:** Join on source schema + original identity + text hash + representation identity + verified parent; never on country label, two-dimensional coordinates, or cluster number. Compute declared population, selection, exclusion, missing source, not-fitted, failed and unassigned counts; decide whether the source-group / speech / year dependence and weighting objective support the proposed comparison. Missing coverage is unknown, never substantive absence.
3. **Receipt issuance:** On an authenticated, *private* coordinator host, load accepted original bytes and the canonical decoded Unicode text; verify raw and text hashes and JSON pointer (where available). Construct `SourceReceipt` only from that approved material. Do not place original bytes or source-bearing row-level outputs into any public web bundle, GitHub commit, synthetic fixture, or exported report. Review-only corrected text without an original-offset reconstruction is unsupported and must be withheld until the separately versioned transform is validated.
4. **Evidence and source authorization:** For every finding, test exact supporting and contrary pointer membership, full code-point bounds, representation ID, duplicate/source-family lineage and source split. Explicitly document unavailable, disputed, and excluded sources. Do not open any of the 37 reserved 5–6 October meetings without separate authorization.
5. **Review and statistical authority:** A trusted coordinator adapter—not an authored report and not an exploratory model—builds a `ReviewDecision`. Preserve actual owner labels separately from assistant-provisional review. Freeze a report digest after reviewer/privacy clearance and set source/reviewer/privacy/statistical verdicts independently; use `not_run` for absent tests. Research-level statistical acceptance must come from the *applicable* accepted research contract, including failed/partial fit accounting, dependence and calibration, not merely a successful cluster fit. If unestablished, set `statistical_gate="not_run"`; the descriptive section may still be displayed with accepted source and review gates. Reviewer interpretation must be separately approved by exact finding ID.
6. **Attribution and stance:** Independently bind source-spanned first-person actor/action/object evidence for a country-level expression; a collective intervention or registry affiliation is not an individual national statement. Position evidence must identify a proposition, a matching text digest, position and exact supporting pointer, then receive a reviewer adjudication. Neither clustering nor a source speaker flag alone satisfies this requirement.
7. **Offline rendering:** Supply only safe, digest-approved copy and trusted in-memory receipts/decisions to `render` or `export`. Verify JSON/Markdown/HTML byte-level reproducibility, source pointer integrity, missing/failed states, accessibility, no transcript excerpts, no tokens, and all output hashes. Ensure untrusted optional keys are rejected rather than silently echoed.
8. **Operational adoption is separate:** The coordinator proposes a **new**, scoped integration PR for accepted presentation components. Run existing R/Shiny, D1 O1–O5, quick-reader, review, source-provenance, browser saved-run and Outlook **non-send** regressions as applicable. The `research/diplomatic_readouts` tree must never write daily adapters, Outlook drafts, manifest/release assets, Shiny code or shared browser entry points. No website mirror, email, public publication, or PR merge follows from this draft worker PR.
