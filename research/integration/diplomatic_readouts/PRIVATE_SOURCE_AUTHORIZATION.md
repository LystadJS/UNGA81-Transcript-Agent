# Private-source authorization — prospective contract v0 (NOT RUN)

**Status:** DESIGN ONLY. This proposal is an interface specification, **not** approval to retrieve, open, analyze, release or publish real UN text. The 37 reserved 5–6 October meetings remain sealed. Neither PR #89's adapter nor PR #70's renderer has authority to issue source, reviewer, statistical, privacy, D1, or deployment approvals.

## Trust boundaries and separately accountable owners

1. **Acquisition and registry authority (future private coordinator host only):** The authoritative inventory must identify upstream source schema, fixed source/selection hashes **with their respective hash bases**, original byte identities, source URL, source family, parent, meeting, date/split, duplicate lineage, whether missing/unavailable, read permission, retention and privacy classification. Persist the original byte SHA-256 separately from the canonical UTF-8 text SHA-256. A content-addressed digest of bytes received from an untrusted submitter proves only consistency, **not authenticated provenance**. Unverified country and speech remain null. Source registry version and provenance decision must be authenticated independently of the report and interchange.
2. **Source eligibility and original text authentication:** Verify each record from an authorized original-source registry and approved original bytes, not an author-supplied `UpstreamValidation` dataclass. Exact JSON pointer, raw-byte hash, decoded code-point hash, text representation/version, parent/hash, span bounds and source family must match. A corrected text layer requires its own versioned offset mapping; never silently reinterpret original spans. Unavailable inventory remains missing, not an issue absence.
3. **Population/method authorization:** Apply canonical `un.parallel-analysis.v1` structural **and** relational validators, exact cohort and selection digests, missing/excluded/not-fitted/noise denominators, source-group dependence and weighting/fit identities. A saved cluster or embedding does not establish significance, coordination, stance, or diplomatic agreement. Development testing never unlocks protected evaluation.
4. **Human reviewer decision:** An *actual* authorized owner/assigned reviewer examines every proposed source-spanned expression and its contrary material. Approval for individual country attribution requires exact first-person actor/action/object support, separately from registry affiliation or collective statement. A stance approval binds exact proposition ID + proposition text digest + relevant evidence pointer + label. Assistant-provisional annotations cannot become human gold.
5. **Privacy authority:** Independently approve what *metadata and prose*, not merely which source, may be exported. Run adversarial excerpt/credential/injection scans, source privacy policy and minimal-disclosure review on the final rendered output. Keep all original bytes, private registry rows and reviewer materials on an authorized private host; never include them in GitHub, CI artifacts, site bundles, log traces, emails or generated public JSON.
6. **Statistical authority:** Require the applicable accepted research gate separately. A successful synthetic suite, fitted cluster, within-sample stability or bootstrap is insufficient. Withhold exploratory interpretation if source dependence, null calibration, period comparability, selection or fit identification remain unresolved. A descriptive readout can only be authorized when its own source/review/privacy gates pass.
7. **D1 O1–O5 and delivery:** A separate operational release authority must explicitly approve each consumer integration. No adapter decision may change a D1 gate, send mail, update Outlook drafts, modify Shiny/browser code, add a public producer, alter release manifests, access protected holdout text or deploy the website.

## Portable public request envelope

`private_source_contract.v0.schema.json` and `private_source_contract.py` implement **only a synthetic, non-authorizing design preview**, `un.private-source-authorization.proposal.v0` (not an authorization token). The envelope contains source/selection/envelope digests, aggregate counts, and explicit `NOT_RUN` statuses for every private-source/reviewer/statistical/publication gate. It has no original-source bytes, row-level material, source URL, paths, credentials, signature or ability to mark a gate `PASS`. Every preview has `authority=none`, `authorized=false`, `publication_eligible=false`, `delivery_eligible=false` and `transcripts_opened=0`. The required keys are closed and fail-closed against additions or unsupported escalation. Digests are reproducibility checks, **not** original-source signatures.

A later independent private-host **v1** issuer, if expressly authorized, would need distinct externally authenticated and revocable records, at minimum: issuer/subject/purpose/scope, registry and original-source provenance receipts, byte/text/representation and selection hashes, exact approved cohort and spans, reviewer action identity and actual choices, privacy authorization, statistically identified research release status, expiry/revocation, audit event ID and cryptographic issuer authentication. Each authority must be able to say `FAIL` or `NOT_RUN` independently; no booleans from authored input can confer authorization. That v1 design is **not implemented** or approved here.
