# I8: local neural training paths and method accounting

**29 standalone research kernels now have synthetic engineering tests: 27 R
kernels plus two Python neural paths. The daily pipeline still has 12 adapters.**
M26 remains unavailable. These counts describe computational implementations,
not 41 fully validated scientific methods or permission to publish results.

## What was added

**M16:** a local BERT checkpoint/tokenizer loader, complete encoder fine-tuning
for one named binary target, independent temperature calibration, abstention,
held-out scores, safe model serialization and prediction reload. Checkpoint
assets are bound by hashes and a hashed manifest. Network access and remote
custom code are not required; only the built-in BERT architecture is supported.
The engineering cap is 10 million parameters, four layers, hidden size 128,
64 input tokens, 512 rows per partition and CPU execution. Longer passages
are rejected rather than silently truncated. The fixed 60-update, learning-rate
0.002 policy is for engineering, not a recommendation for real-world fine-tuning.

The test fixture creates a tiny BERT encoder and performs 15 masked-token
pretraining updates on fictional strings before fine-tuning. Its classifier
and pooler are newly initialized, explicitly reported, and then trained.
This verifies checkpoint loading and gradient updates; it does not establish
the quality of an approved natural-language checkpoint or diplomatic labels.
The actual encoder weights change during the test, not only a classifier head.

**M38:** a one-layer, unidirectional GRU with 16 hidden units, trained for a
binary outcome at the next comparable observation. This implements the
sequence-model option of the registered method; it is not a temporal transformer.
Variable observation windows contain 2–32 steps and up to 32 features.
Normalization uses training observations only. Packed sequences exclude padded
values from the recurrent state. Future or unavailable observations, overlapping
evaluation histories, missing features and undeclared comparability are rejected.
An independent, regularized last-observation logistic baseline uses the same
partitions and calibration policy. This is a matched baseline, not a direct
cross-language replay of the M37 R implementation.

Both paths require disjoint country/content/observation groups and forward-time
training, calibration and test partitions. A named target is mandatory.
Scores use a temperature chosen only from calibration outcomes and a fixed
0.3/0.7 abstention policy. Changing test labels cannot change fitted weights or
predictions. Every result retains `publication_eligible=false` and
`daily_adapter_integrated=false`. Real or unreviewed input is still rejected.

## Run locally

Use an isolated Python 3.12 environment; 3.12 was the tested version. From the
repository root on Windows:

```powershell
python -m venv research/neural-env
research/neural-env/Scripts/python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cpu
research/neural-env/Scripts/python -m pip install -r research/neural-requirements.txt
research/neural-env/Scripts/python research/test_neural.py
python research/test_methods.py
python research/methods.py
```

This installs software packages, not pretrained model weights. Training and
prediction use local files. Tested direct versions: torch 2.10.0+cpu,
transformers 4.57.6, safetensors 0.7.0, tokenizers 0.22.2 and numpy 2.3.5.
Torch and Transformers versions are checked for training; runtime versions
are recorded in every output. Separate neural and R libraries preserve the
daily pipeline's frozen dependency identity.

To create inspectable fictional inputs, a synthetic pretrained checkpoint,
trained models and reports, choose a **new** output directory:

```powershell
research/neural-env/Scripts/python research/demo_neural.py research/runs/my-demo
```

The demo writes `M16.json`, `M38.json`, a synthetic checkpoint, two saved result
directories and `summary.json`. Its fields are runnable input-schema examples.
These artifacts are ignored by Git. Do not label them reviewed UN data.

The two methods can also run independently:

```powershell
research/neural-env/Scripts/python research/neural.py M16 research/runs/my-demo/M16.json research/runs/new-text-run
research/neural-env/Scripts/python research/neural.py M38 research/runs/my-demo/M38.json research/runs/new-sequence-run
```

Each result directory contains `model.safetensors`, `result.json`, and a checksum
manifest; the text path also saves its tokenizer/configuration. Output directories
cannot be overwritten. An interrupted write may leave an incomplete directory;
the reloader rejects it. Input hashes bind the bytes actually read, not a later
version of the input file. `predict_saved` verifies all saved members and reuses
the saved calibration and normalization. Text-token budgets and sequence feature
order/representation must match the saved run.

## Remaining M26 dependency

The registry names **driftmapR movement/resampling** and refers to an earlier
experimental adapter and supported-regime study. The current repository and
referenced UI conversation contain no usable package URL, version, interface
or study artifact. An exact-name GitHub repository search returned no match.
That is not proof the package does not exist; it may be private or local.

Provide the original package/repository path, pinned commit/version, supported
input regime and calibration/resampling study. Until then, M26 stays
`not_implemented`. No generic bootstrap is substituted under that name.

## Recommended next steps

1. Locate the original driftmapR source and supported-regime evidence.
2. Complete a small independent annotation pilot using the
   [dataset guide](../docs/DATA_GUIDE.md), including adjudication and a frozen
   split policy. Select an approved text checkpoint/tokenizer and record its
   license, provenance and evaluation scope.
3. Build a source-bound reviewed-bundle loader and fit baseline models first.
   The current checker cannot certify reviewer identity, truthful labels or
   scientific validity; setting a metadata flag must not authorize deployment.
4. Assemble comparable historical panels, define the observation horizon and
   evaluate sequence models against the simpler baseline. Add learning curves,
   calibration/abstention analysis, uncertainty and resource benchmarks.
5. Integrate accepted methods as audit-only daily adapters, then run full replay
   and live Shiny/Outlook acceptance before considering publication changes.
